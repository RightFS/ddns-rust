# Namecheap first-party SDK contract update

Research/implementation date: 2026-11-09. This corrects the blanket Namecheap deferral in the older registrar research. A REAL narrow BasicDNS plain-host adapter is now justified; catalog enablement and integration are the parent's responsibility. No production/sandbox DNS API calls, credentials, SDK execution, support contact or account login were used. Tests use localhost only. Direct Namecheap documentation fetches were navigation-truncated; official content was retrieved through Jina text transport, with the underlying Namecheap URLs cited below. Public GitHub SDK source was read directly. Do not run the SDK acceptance suite: its EmailType tests intentionally empty disposable zones, even in production.

## Local integration outcome

Parent integration completed on 2026-11-09: Namecheap is enabled within the explicit narrow scope, with 19 adapter regressions plus configuration/API/Web integration tests. The complete project passed **558 Rust tests, 32 Web VM tests, 24 release configuration checks, strict all-target Clippy/format/release gates, and a 41-request local release HTTP smoke**. No real/sandbox Namecheap request, account acceptance or DNS propagation was tested. Final rolling counts and remaining providers are maintained in [full progress](<../PROVIDERS.md>).

## Corrected contracts

- [Website setHosts](https://www.namecheap.com/support/api/methods/domains-dns/set-hosts/) still marks EmailType required, although examples omit it. The first-party [mail-mode source](https://github.com/namecheap/go-namecheap-sdk/blob/33ba8d7853be1b4894e8572264700ff4a8a002d5/namecheap/domains_dns_email_type.go), [SDK API reference](https://github.com/namecheap/go-namecheap-sdk/blob/33ba8d7853be1b4894e8572264700ff4a8a002d5/docs/namecheap-api-v2.md), merged [PR199](https://github.com/namecheap/go-namecheap-sdk/pull/199), and [maintainer explanation](https://github.com/namecheap/go-namecheap-sdk/issues/162#issuecomment-6627915992) explicitly correct this: omitting EmailType preserves the zone's current mode, observed on sandbox and production 2026-10-08. MX rows survive only under MX; MXE survives MX/MXE, but is published only under MXE. Unknown mode can return Status=OK without Errors yet IsSuccess=false. These are explicit first-party server-behavior observations, not assumptions from third-party SDK omission.
- OX/FWD/GMAIL presets synthesize mail records from the mode. Their MX/SPF/autodiscover/SRV may be absent from getHosts, including active production Private Email. An A-only host inventory CAN therefore contain hidden mail state, but omission preserves it; reconstructing MX from DNS lookup is neither necessary nor safe. The adapter reads and verifies current getHosts EmailType and never sends it.
- The [actual getHosts XML fixture](https://github.com/namecheap/go-namecheap-sdk/blob/33ba8d7853be1b4894e8572264700ff4a8a002d5/namecheaptest/fixtures/domains_dns_getHosts.xml) contains result EmailType and each row's HostId/Name/Type/Address/MXPref/TTL/AssociatedAppTitle/FriendlyName/IsActive/IsDDNSEnabled. The [pointer-valued raw model](https://github.com/namecheap/go-namecheap-sdk/blob/33ba8d7853be1b4894e8572264700ff4a8a002d5/namecheap/domains_dns_get_hosts.go) distinguishes omitted attributes. Website response-table/sample omissions are NOT proof actual responses lack those fields.
- [getInfo raw model](https://github.com/namecheap/go-namecheap-sdk/blob/33ba8d7853be1b4894e8572264700ff4a8a002d5/namecheap/domains_get_info.go) exposes DnsDetails HostCount/EmailType/DynamicDNSStatus/IsFailover/provider/nameservers plus ownership, domain expiry and PremiumDnsSubscription. [Actual getInfo fixture](https://github.com/namecheap/go-namecheap-sdk/blob/33ba8d7853be1b4894e8572264700ff4a8a002d5/namecheaptest/fixtures/domains_getInfo.xml) shows these fields; its FreeDNS domain is NOT an eligible adapter fixture. BasicDNS uses observed ProviderType=ENOM, not an invented literal BasicDNS. [getList XML](https://github.com/namecheap/go-namecheap-sdk/blob/33ba8d7853be1b4894e8572264700ff4a8a002d5/namecheaptest/fixtures/domains_dns_getList.xml) supplies OurDNS/FreeDNS/PremiumDNS flags. Independent exact default nameserver checks additionally constrain scope.
- [First-party transport](https://github.com/namecheap/go-namecheap-sdk/blob/33ba8d7853be1b4894e8572264700ff4a8a002d5/namecheap/namecheap.go) POSTs URL-encoded parameters to xml.response, Content-Type application/x-www-form-urlencoded. Authentication globals go in the form along with Command/SLD/TLD and indexed HostName/RecordType/Address/TTL/MXPref. The RESPONSE is XML; neither XML request bodies nor the confusing website authDetails JSON example are used. [Global parameters](https://www.namecheap.com/support/api/global-parameters/) identify ClientIp as the server's IPv4, not the DDNS target. This initial implementation uses APIUser=UserName for the owned account only.
- [getHosts](https://www.namecheap.com/support/api/methods/domains-dns/get-hosts/) has no page/filter/continuation request and returns one host array; first-party helpers use full read-modify-write. This legitimate complete-array contract does not require invented proof against a malicious API. [DNS limits](https://www.namecheap.com/support/knowledgebase/article.aspx/10058/10/namecheap-dns-limits/) and [BasicDNS](https://www.namecheap.com/support/knowledgebase/article.aspx/923/10/what-is-your-basicdns/) publish 800 records; >800 errors. The >10 POST recommendation is NOT a zone cap. Reject explicit warnings/truncation signals, excessive records and supplied HostCount mismatches.

## Accepted narrow implementation

[Adapter](<../src/providers/namecheap.rs>) and [disabled example](<../examples/namecheap.toml>) require scope=basicdns_plain, write_mode=exclusive_full_zone, explicit production/sandbox, explicit sld/tld with exact configured domain equality and a bounded NAMECHEAP_-scoped server egress IPv4 environment reference. Fixed endpoints only; no environment fallback, endpoint overrides or cloud probes. Constructor credentials/ClientIp must be preflight-checked by integration before IP-source I/O. Caller must use verified TLS, redirect Policy::none and retry::never.

The adapter obtains getInfo, dns.getList and full getHosts. It requires owned nonexpired registered ENOM/BasicDNS, exact default nameservers and OurDNS, nonPremium/nonFree, domain DynamicDNSStatus=false and IsFailover=false. Domain registrar status Locked is accepted as nonexpired registration status, not confused with disabled DNS. Every row must explicitly be IsActive=true, IsDDNSEnabled=false, with empty AssociatedAppTitle/FriendlyName. Missing/unknown controls, unsupported attributes/types, warnings, duplicate native IDs, malformed inventory or explicit count inconsistency fail before unchanged/dry-run/planning/write. EmailType must be known NONE/MX/MXE/FWD/OX/GMAIL; MX host rows are allowed only in MX mode. Initial representable unrelated types: A/AAAA/TXT/CNAME/NS/MX. MXE/CAA/ALIAS/SRV/URL/URL301/FRAME are deliberately excluded until individual preservation proof.

Native Name is kept raw and interpreted only by documented relative semantics (@ apex and legal multilabel relative names); trailing-dot owners are refused, not guessed from zone suffixes. Native values, explicit TTL60..60000 and MXPref are copied verbatim. Initial eligibility additionally requires canonical decimal spelling, and the first-party-observed non-MX preference `10`; other spellings/preferences reject before planning. This is an initial adapter subset restriction, NOT an alleged API rule. Only the selected target's effective IP is compared semantically during readback (including equivalent IPv6 spellings); all unrelated addresses remain byte-exact. Unrelated duplicate rows are retained as a multiset. Target A/AAAA owner/type must be a singleton; CNAME/delegated NS conflicts fail before any plan. Only stable owner/type logical namecheap-SHA256 target IDs are accepted; actual HostId is opaque before-snapshot metadata and never sent. No guarantee that HostIds never rotate is asserted; readback comparison deliberately excludes native IDs.

List reads the entire array before locally returning only the singleton target; its extra carries the full unrelated array and context without credentials/contact data/DynamicDNSPassword. Update compares the initial complete snapshot against two fresh full snapshots. Create requires explicit opt-in, and two fresh complete absence snapshots. One indexed form replacement omits EmailType, checks HTTP200/StatusOK/noErrors/command/domain/IsSuccess=true, then verifies full record multiset/TTL/control/mailmode/context readback. Failures after dispatch are uncertain, never success or automatic resend. Exclusive writer consent is an operational assumption, not a lock/CAS guarantee; DNS propagation is not claimed.

## Remaining exclusions and limitations

No authoritative inactive-record setter or inactive-preserve guarantee was found. This does NOT prove BasicDNS lacks disabled records. The official [Host Records guide](https://www.namecheap.com/support/knowledgebase/article.aspx/434/2237/how-do-i-set-up-host-records-for-a-domain/) describes HTTPS toggles as SSL/CDN automation, not DNS activation. Initial active-only eligibility avoids that ambiguity.

Precise HostCount semantics for synthesized preset mail were not established. If supplied, the count must match the actual host-array length; any mismatch rejects rather than forcing equality by inventing/excluding hidden records. Preset mail remains governed by the preserved mode. Native SRV is documented but absent the API setHosts allowed list: reject returned SRV, do not invent unseen/truncated SRV guarantees. Parent must not expose broad whole-zone compatibility or per-record CAS. Public fixtures plus localhost request/response tests are sufficient for offline validation; no production test writes are requested.

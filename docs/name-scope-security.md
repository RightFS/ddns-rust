# DNS 名称作用域安全修复

更新：2026-11-09。此说明记录代码审查和本地回归，不代表线上云账号验收。

## 问题

旧协调器同时接受 API 记录名称等于配置相对名或完整域名。这无法区分 API 使用的名称约定，可能误选后缀碰撞记录：

- 区域 `example.com`，配置相对名 `home`，期望 `home.example.com`。
- 相对名称 API 返回 `home.example.com`，实际表示 `home.example.com.example.com`。
- 旧比较把该相对名当成配置完整域名，可误选该记录。
- 反方向也成立：完整域名 API 返回 `home.example.com`，不应匹配配置相对名 `home.example.com`（期望双重区域后缀）。

HiPM 的 Aliyun 映射还曾通过“已有区域后缀”猜测相对 RR 为完整域名。选中检查、快照与读回复用同一错误模型，不能独立救济这种作用域错误。

## 修复

- [协调器](<../src/providers/common.rs#L63-L90>)要求每个适配器明确声明解析后模型的 `NameFormat::Relative` 或 `Fqdn`；不提供两种约定同时接受的模式。
- 候选计数与显式 ID 匹配只使用正确约定，早于 unchanged、只读计划和写入。
- HiPM 已审计 Aliyun 原生 RR：只有 `@` 表示根；其他合法相对名始终追加区域。原生 RR 保留在写入载荷，不截断合法多级相对名。
- Vercel 的相对名目标、回执与子域 NS 委派判断改用一致的相对名规则；AliDNS、传统 DNSPod、Porkbun 增加直接更新的作用域防御。
- ClouDNS 的目标与创建回执校验不再接受相对名/FQDN 混用。

## 本地回归

新增 15 项通用与服务商测试（参数化覆盖多种场景），以及 4 项 HiPM 测试：错误主机在相等 IP、只读、真实更新和显式 ID 情况下不能被误选；碰撞记录与真正目标同时存在时只选真正目标；合法多级相对记录可更新且原生名称不被改写；多级子域 NS 委派被正确识别。

修复后首次完整编译验证包含 491 项单元/API 测试与 5 项 CLI 测试，严格 Clippy、格式检查通过；Release 重建与 11 项 Web VM/DOM 桩回归通过。该测试数量包含尚在接线阶段的第七批适配器测试，不等于可用服务商数量；当前最终进度请见[全量进度](<../PROVIDERS.md>)。

## 已有部署建议

重新构建并替换旧二进制，先保持目标禁用，再执行只读诊断，核对实际区域、相对记录名和原生/逻辑 ID。尤其检查相对主机名中包含区域文本的记录。合法多级相对主机不需要为了规避错误而重命名。

日志脱敏不会隐藏域名、公网 IP、RequestId 等业务信息；分享诊断前仍需检查。没有发现或确认任何真实账号受到该问题影响，本轮未执行真实云 DNS 读取或写入。
